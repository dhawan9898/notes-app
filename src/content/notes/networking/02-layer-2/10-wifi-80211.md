Wi-Fi is Ethernet without the wire. It carries the same IP packets, but the medium is a **shared, noisy, half-duplex radio channel**: only one device on a channel can usefully transmit at a time, signals fade, collide and cannot be heard by everyone, and anyone in range can listen. Almost everything specific to 802.11 exists to cope with those facts: a different medium-access method, per-frame acknowledgments, extra address fields, mandatory encryption and a join procedure.

## Architecture

- A **station (STA)** is any wireless client. An **access point (AP)** connects stations to the wired network and relays between them. An AP and its stations form a **basic service set (BSS)**, identified at Layer 2 by the AP radio's MAC address, the **BSSID**.
- The human-readable network name is the **SSID**. Several APs sharing an SSID and wired network form an **extended service set (ESS)**, which is how roaming works across a building.
- Large deployments use **controllers** (CAPWAP, RFC 5416, and vendor variants) or cloud management to configure many APs, assign channels and power, and handle roaming and policy.
- A wireless AP is a **bridge**: the wireless side and the wired side are one Layer 2 network (often mapped to a VLAN per SSID), so the VLAN and Layer 2 security material of this module applies.

## Spectrum: bands, channels and generations

| Band | Channels | Character |
|---|---|---|
| **2.4 GHz** | 1 to 13 (14 in Japan), 20 MHz wide, only **three non-overlapping** (1, 6, 11 in most regions) | longest range, best wall penetration, crowded (also Bluetooth, microwave ovens) |
| **5 GHz** | many 20/40/80/160 MHz channels; some require **DFS** (radar detection and avoidance) | much more capacity, shorter range |
| **6 GHz** (Wi-Fi 6E, 7) | up to seven 160 MHz or three 320 MHz channels; WPA3 mandatory; no legacy devices | cleanest, shortest range |

| Name | Standard | Year | Highlights (theoretical maximum link rates; real throughput is far lower) |
|---|---|---|---|
| Wi-Fi 4 | 802.11n | 2009 | MIMO, 40 MHz channels, up to 600 Mbit/s |
| Wi-Fi 5 | 802.11ac | 2013 | 5 GHz only, 80/160 MHz, 256-QAM, downlink MU-MIMO, up to a few Gbit/s |
| Wi-Fi 6 / 6E | 802.11ax | 2019/2020 | **OFDMA** (split a channel among several clients in one transmission), 1024-QAM, BSS colouring, target wake time, 6 GHz |
| Wi-Fi 7 | 802.11be | 2024 | 320 MHz, 4096-QAM, **multi-link operation** (use several bands at once) |

Advertised figures ("AX3000") are the sum over bands of the maximum PHY rate. Real-world throughput is typically half the link rate or less, because of protocol overhead, contention and signal conditions, and it is **shared by everyone on the channel**.

## Medium access: CSMA/CA

Ethernet's old CSMA/**CD** detected collisions while transmitting; a radio cannot listen while it sends. 802.11 therefore uses **collision avoidance** in its Distributed Coordination Function (DCF):

1. **Listen first** (carrier sense). If the channel has been idle for a **DIFS** interval, transmit; if busy, wait.
2. If the channel was busy, after it clears choose a random **backoff** of 0 to `CW` slots and count down only while the channel is idle. The first station to reach 0 transmits.
3. The receiver sends an **ACK** after a short gap (**SIFS**, shorter than DIFS, so ACKs always win the channel). No ACK means a collision or corruption: the sender **doubles its contention window** (binary exponential backoff, from 15 up to 1023 slots) and retries, up to a retry limit, then drops the frame.
4. **Hidden nodes**: two stations may each hear the AP but not each other, so carrier sense fails and their frames collide at the AP. The optional **RTS/CTS** handshake fixes this: a short Request-to-Send is answered by a Clear-to-Send that every station in range of the AP hears, and the **NAV** (network allocation vector, a duration field in the frame) tells them to stay quiet.

This is a *random-access* protocol, and its cost grows with the number of contending stations. A simulation (saturated stations, ideal channel, no hidden nodes, contention window 15 to 1023) shows the effect:

```python
#!/usr/bin/env python3
"""Slotted simulation of 802.11 DCF (CSMA/CA with binary exponential backoff), saturated stations, ideal channel (no hidden nodes, no noise).
Every station always has a frame to send. Contention window: CWmin = 15, CWmax = 1023 (OFDM PHY)."""
import random, sys

CW_MIN, CW_MAX, RETRY_LIMIT = 15, 1023, 7
T_SUCCESS, T_COLLISION = 40, 40       # slots a successful exchange / a collision occupies the medium (data + SIFS + ACK, in slot units)

def run(n, slots=2_000_000, seed=1):
    rnd = random.Random(seed)
    cw = [CW_MIN] * n; backoff = [rnd.randint(0, CW_MIN) for _ in range(n)]; retries = [0] * n
    attempts = collisions = successes = drops = 0; busy = 0; per_station = [0] * n; t = 0
    while t < slots:
        m = min(backoff)
        t += m; backoff = [b - m for b in backoff]                       # idle slots while every station counts down
        tx = [i for i in range(n) if backoff[i] == 0]
        attempts += len(tx)
        if len(tx) == 1:
            i = tx[0]; successes += 1; per_station[i] += 1; busy += T_SUCCESS; t += T_SUCCESS
            cw[i] = CW_MIN; retries[i] = 0; backoff[i] = rnd.randint(0, cw[i])
        else:
            collisions += len(tx); t += T_COLLISION
            for i in tx:                                                   # collision: double the contention window and retry
                retries[i] += 1
                if retries[i] > RETRY_LIMIT: drops += 1; cw[i] = CW_MIN; retries[i] = 0
                else: cw[i] = min(2 * cw[i] + 1, CW_MAX)
                backoff[i] = rnd.randint(0, cw[i])
    jain = sum(per_station) ** 2 / (n * sum(x * x for x in per_station))   # Jain's fairness index: 1.0 = perfectly equal shares
    return collisions / attempts, busy / t, jain, drops / max(1, successes + drops)

print(f"{'stations':>8} {'P(collision) per attempt':>26} {'channel efficiency':>20} {'fairness (Jain)':>16} {'frames dropped':>15}")
for n in (1, 2, 5, 10, 20, 50):
    pc, eff, fair, drop = run(n)
    print(f"{n:>8} {pc * 100:>25.1f}% {eff * 100:>19.1f}% {fair:>16.3f} {drop * 100:>14.2f}%")
```

       1                       0.0%                84.2%            1.000           0.00%

- With one station there are no collisions but only about 84 % of airtime carries data: the rest is the idle backoff slots (the cost of the randomisation) before every frame.
- Every added station raises the probability that an attempt collides (a **collision** wastes a whole frame time): from about 11 % with two stations to roughly 60 % with fifty, and channel efficiency falls with it. Real networks fare worse still, since the simulation assumes a perfect channel.
- The sharing is nearly **fair per frame** (Jain's index near 1), not fair per *time*: a slow station that needs ten times longer per frame consumes ten times the airtime for the same number of frames, which is the **anomaly** that drags every client down towards the speed of the slowest (the reason modern APs implement *airtime fairness*, and why legacy low rates are disabled).
- Frames dropped after exhausting retries rise from 0 to about 2 % at fifty stations.

The practical conclusions: keep the number of clients per channel moderate, use more APs on different channels with lower power rather than one powerful AP, disable old data rates, and prefer 5 GHz and 6 GHz for capacity. OFDMA in Wi-Fi 6 partly addresses the contention problem by scheduling several small transmissions in one access.

## The 802.11 frame

The MAC header differs from Ethernet in several ways. A basic data or management frame is:

| Field | Size | Purpose |
|---|---|---|
| Frame Control | 2 | protocol version, **type** (management, control, data), **subtype**, ToDS/FromDS bits, retry, power-management, **protected** (encrypted) flags |
| Duration/ID | 2 | NAV duration in microseconds (or association ID) |
| Address 1 | 6 | **receiver** (the next radio hop) |
| Address 2 | 6 | **transmitter** |
| Address 3 | 6 | usually the BSSID or the far-end source/destination |
| Sequence Control | 2 | sequence and fragment numbers |
| Address 4 | 6 | only for AP-to-AP (WDS/mesh) frames |
| QoS Control | 2 | priority (WMM access category) in QoS data frames |
| Body | variable | payload or management information |
| FCS | 4 | CRC-32 |

The meaning of the three address fields depends on the **ToDS/FromDS** bits (a frame from a station to the AP carries BSSID, source, destination; one from the AP to a station carries destination, BSSID, source). Because a radio frame needs a receiver address even when the final destination is elsewhere, the address model is richer than Ethernet's. There are three **frame types**:

- **Management**: beacons, probe request/response, authentication, association, reassociation, disassociation, deauthentication, action frames.
- **Control**: RTS, CTS, ACK, block ACK, power-save poll.
- **Data**: payload, usually QoS data, wrapped in an LLC/SNAP header so that the EtherType survives.

The script below builds a **beacon** frame, the frame an AP broadcasts about ten times a second to advertise the network, parses it back and prints each field. The frame is constructed by the script according to the standard's field layout (it is not a capture from a radio).

```python
#!/usr/bin/env python3
"""Build an IEEE 802.11 beacon frame byte by byte, parse it back, and derive a WPA2 pairwise master key."""
import hashlib, struct

def mac(s): return bytes(int(x, 16) for x in s.split(":"))
def ie(eid, body): return bytes([eid, len(body)]) + body

# ---- management frame header: frame control, duration, addr1 (receiver/destination), addr2 (transmitter), addr3 (BSSID), sequence control ----
fc = 0x0080                                    # version 0, type 0 (management), subtype 8 (beacon)
bssid = mac("02:00:00:aa:bb:01")
header = struct.pack("<HH", fc, 0) + mac("ff:ff:ff:ff:ff:ff") + bssid + bssid + struct.pack("<H", 42 << 4)
# ---- beacon body: timestamp (8), beacon interval in TUs of 1024 us (2), capability (2), then tagged information elements ----
rsn = struct.pack("<H", 1) + b"\x00\x0f\xac\x04" + struct.pack("<H", 1) + b"\x00\x0f\xac\x04" + struct.pack("<H", 1) + b"\x00\x0f\xac\x02" + struct.pack("<H", 0x000c)  # RSN: group CCMP, pairwise CCMP, AKM PSK, caps
body = struct.pack("<QHH", 123456789, 100, 0x0431) + ie(0, b"DemoNet") + ie(1, bytes([0x8c, 0x12, 0x98, 0x24, 0xb0, 0x48, 0x60, 0x6c])) + ie(3, bytes([6])) + ie(48, rsn)
frame = header + body
print(f"beacon frame: {len(frame)} bytes (+4 byte FCS on the air)")
print("hex:", frame.hex(" ")[:96], "...")

# ---- parse it back ----
f0, dur = struct.unpack("<HH", frame[:4]); ftype, subtype = (f0 >> 2) & 3, (f0 >> 4) & 15
print(f"\nframe control 0x{f0:04x}: version {f0 & 3}, type {ftype} ({['management', 'control', 'data'][ftype]}), subtype {subtype} (beacon), ToDS={f0 >> 8 & 1}, FromDS={f0 >> 9 & 1}, protected={f0 >> 14 & 1}")
print("addr1 (destination):", ":".join(f"{b:02x}" for b in frame[4:10]), "  = broadcast: every station in range")
print("addr2 (transmitter):", ":".join(f"{b:02x}" for b in frame[10:16]), " addr3 (BSSID):", ":".join(f"{b:02x}" for b in frame[16:22]))
ts, interval, cap = struct.unpack("<QHH", frame[24:36])
print(f"timestamp {ts} us, beacon interval {interval} TU = {interval * 1.024:.1f} ms, capability 0x{cap:04x} (ESS={cap & 1}, privacy={cap >> 4 & 1})")
off = 36; names = {0: "SSID", 1: "Supported rates", 3: "DS parameter set (channel)", 48: "RSN (WPA2/WPA3 security)"}
while off < len(frame):
    eid, ln = frame[off], frame[off + 1]; v = frame[off + 2:off + 2 + ln]
    shown = v.decode() if eid == 0 else (f"channel {v[0]}" if eid == 3 else ("[" + ", ".join(f"{(x & 0x7f) * 0.5:g}{'*' if x & 0x80 else ''}" for x in v) + "] Mbit/s (* = basic rate)" if eid == 1 else v.hex()))
    print(f"  IE {eid:>2} {names.get(eid, '?'):<28} len {ln:<2} {shown}"); off += 2 + ln
print("  RSN detail: group cipher 00-0f-ac:4 (CCMP/AES), pairwise CCMP, AKM 00-0f-ac:2 (WPA2-PSK)")

# ---- WPA2-Personal: the pairwise master key (PMK) is PBKDF2-HMAC-SHA1(passphrase, SSID, 4096 iterations, 256 bits) ----
pmk = hashlib.pbkdf2_hmac("sha1", b"password", b"IEEE", 4096, 32)
vector = "f42c6fc52df0ebef9ebb4b90b38a5f902e83fe1b135a70e23aed762e9710a12e"          # test vector from IEEE Std 802.11i-2004 Annex H.4
print("\nPMK for passphrase 'password', SSID 'IEEE':", pmk.hex(), "\nmatches the 802.11i test vector:", pmk.hex() == vector)
```

Reading it: frame-control `0x0080` means type 0 (management), subtype 8 (beacon); the destination is the broadcast address; transmitter and BSSID are the AP's radio address. The beacon body carries a timestamp for clock synchronisation, the **beacon interval** (100 time units of 1.024 ms ≈ 102.4 ms), capability bits (the *privacy* bit says encryption is required), and a series of **information elements**: the SSID, the supported data rates (the starred ones are *basic rates* every client must support), the channel number and the **RSN element** which advertises the security suite (here WPA2-Personal with AES-CCMP). Clients that **scan passively** listen for beacons on each channel; **active** scanning sends **probe requests** and APs answer.

## Joining: scan, authenticate, associate, secure

1. **Scan** for networks (beacons or probes) and pick a BSS by SSID and signal.
2. **Authentication** (802.11 "open system" is only a formality; in WPA3 the **SAE** exchange happens here).
3. **Association**: the station asks to join and the AP assigns an **association ID**; capabilities (rates, 802.11n/ac/ax features, power-save) are exchanged.
4. **Security handshake**: for WPA2/WPA3-Personal, the **4-way handshake** proves both sides know the key and derives fresh per-session encryption keys; in Enterprise mode an **802.1X/EAP** exchange with a RADIUS server comes first (see *Layer 2 Security*).
5. **IP configuration**: DHCP (or SLAAC) as on any LAN.

## Security

| Generation | Mechanism | Status |
|---|---|---|
| **WEP** | RC4 with a static key | broken in minutes; never use |
| **WPA** (TKIP) | interim fix | deprecated |
| **WPA2-Personal** | pre-shared key; AES-CCMP encryption; 4-way handshake | still ubiquitous; vulnerable to **offline dictionary attacks**: capture one handshake, then guess passphrases at leisure |
| **WPA2/WPA3-Enterprise** | 802.1X with EAP-TLS/PEAP, individual credentials, RADIUS | recommended for organisations |
| **WPA3-Personal** | **SAE** (a password-authenticated key exchange): each guess requires an interaction, so offline cracking is no longer possible; forward secrecy | current; mandatory with 6 GHz |
| **OWE** ("Enhanced Open") | unauthenticated Diffie-Hellman for open networks | encrypts guest networks against passive snooping |
| **PMF** (802.11w) | protects management frames (deauthentication) from forgery | required by WPA3; defeats trivial deauth attacks |

In **WPA2-Personal** the passphrase is turned into the **pairwise master key (PMK)** with a deliberately slow function: `PMK = PBKDF2-HMAC-SHA1(passphrase, SSID, 4096 iterations, 256 bits)`. The SSID is the salt, so the same passphrase on different SSIDs gives different keys. The beacon script above implements it with Python's standard library and checks it against the test vector published in IEEE 802.11i (passphrase `password`, SSID `IEEE`): the computed key matches. The security of a PSK network is therefore exactly the strength of the passphrase, because an attacker who captures the 4-way handshake can test guesses offline at the speed of a GPU. Use long random passphrases, or WPA3/Enterprise.

## Roaming

A client moves between APs of the same ESS by **reassociating**; the client decides when (typically below about −70 to −75 dBm), which makes poorly chosen thresholds a common cause of "sticky clients". Standards help the decision and speed it up: **802.11k** (neighbour reports: which APs to try), **802.11v** (the network can suggest a move), and **802.11r** (**fast BSS transition**: pre-derived keys avoid a full handshake, cutting the gap to tens of milliseconds, important for voice). **Mesh** and WDS links connect APs over radio; each wireless hop that shares the client channel roughly halves throughput.

## Troubleshooting

Think in layers: radio first, then association, then IP.

| Symptom | Likely cause | What to check |
|---|---|---|
| Slow despite "full bars" | contention or co-channel interference, low data rates, retries | channel utilisation and retry rate; scan neighbours; use 5/6 GHz |
| Connects but no IP | DHCP failure or VLAN mapping | DHCP logs, `169.254.x.x` address on the client |
| Drops when moving | sticky client or no fast roaming, too-low power, AP coverage gaps | client roam logs; signal at the edge; enable 802.11k/v/r |
| Cannot join / authentication fails | wrong passphrase, WPA mode mismatch, 802.1X certificate or RADIUS problems, PMF required but unsupported | AP and RADIUS logs |
| Works at 5 GHz, fails at 2.4 (or the reverse) | band steering, DFS channel event, regulatory domain | AP radio logs; fixed channels |
| Poor voice/video | no QoS (WMM), roaming gaps, retries | WMM enabled; DSCP to access-category mapping |

Typical signal guidance: received signal strength better than about −65 dBm and a signal-to-noise ratio above 25 dB for good service, but the number that matters most is **airtime**: how busy the channel is and how many frames are retried. On Linux (reference commands; this environment has no wireless hardware, so none were run for this note): `iw dev wlan0 link` (current AP, signal, bitrate), `iw dev wlan0 scan` (neighbouring networks), `nmcli device wifi list`, `iw dev wlan0 station dump` (per-station statistics on an AP, including retries and bitrates), and a monitor-mode capture (`iw dev wlan0 set type monitor`) analysed in Wireshark for the frames above.

## Key takeaways

1. Wi-Fi is a shared, half-duplex, lossy medium: 802.11 uses CSMA/CA with random backoff, per-frame ACKs and optional RTS/CTS for hidden nodes.
2. Contention costs grow with the number of stations; one slow client consumes the airtime that faster ones could use.
3. The 802.11 header carries up to four addresses whose meaning depends on ToDS/FromDS; management frames (beacons, probes, association) build and maintain the network.
4. WPA2-Personal security is only as strong as the passphrase (offline cracking); WPA3-SAE and 802.1X Enterprise remove that weakness; PMF protects management frames.
5. Roaming is client-driven; 802.11k/v/r help make it fast; capacity comes from more APs on more channels at lower power, not louder APs.

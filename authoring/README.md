# Authoring tools

Notes for the **C** and **DSA** tracks are generated from templates so that every code listing and every command output shown on the site comes from code that was actually compiled and run.

```text
authoring/
  templates/<track>/<module>/<note>.md   # note source with {{include ...}} and {{run ...}} directives
  examples/<track>/<topic>/*             # the C sources, Makefiles and scripts the notes embed
  build.py                               # assembles templates into src/content/notes/
```

Directives (one per line):

| Directive | Effect |
|---|---|
| `{{include c/dir/file.c}}` | embeds the file as a fenced code block (`{{include c/dir/file.c 10-30}}` for a line range) |
| `{{run c/dir :: command}}` | runs `command` in `authoring/examples/c/dir` and embeds `$ command` plus its output |

```bash
python3 authoring/build.py                 # rebuild all templated notes (needs gcc, g++, make, cmake, python3)
python3 authoring/build.py strings dynamic # rebuild only templates whose path contains one of the words
npm run build                              # validate front matter and build the static site
```

Compiled binaries and object files are git-ignored (`authoring/examples/.gitignore`); `build.py` regenerates them on demand. Some outputs (timings, addresses, random tokens) differ between runs; the surrounding text describes the *shape* of the result, not exact numbers.

The Networking and Linux notes are written directly in `src/content/notes/` (their command outputs were captured from real runs, but are not regenerated by the build).
